# Code Siege v2: notes

Apocalyptic base-defence + PvP game for the IETE-SF fest, served at `/siege` inside a small site shell.
This file tracks decisions and how to run things. The brief is the source of truth for scope.

## How to run

Needs Node.js 22.

```bash
npm install
npm run dev      # site + game on http://localhost:5173/siege/ (hot reload); game server on :3000
npm test         # combat engine, economy, server rules, persistence
npm start        # production: builds the site, one process serves everything on :3000
```

Phones on the same wifi use the LAN address printed at startup.

| Page | URL |
|---|---|
| Game | `/siege/` |
| Live Arena (watch only, no login) | `/siege/arena/` |
| Projector (auto-cycles battles, big leaderboard when idle) | `/siege/arena/?projector=1`, then press Fullscreen |

| Setting | Where | Default |
|---|---|---|
| Game server address (client) | `VITE_SIEGE_SERVER_URL` in `client/.env` | same address as the page |
| Game server port / bind | `SIEGE_PORT`, `SIEGE_HOST` | `3000`, `0.0.0.0` |
| Database file | `SIEGE_DB` | `server/data/siege.db` |
| Crate question bank | `SIEGE_QUESTIONS` | `server/data/questions.json` |
| Admin passphrase | `SIEGE_ADMIN_PASS` (or `server/.env`) | empty = admin off |
| Backups folder | `SIEGE_BACKUPS` | `server/data/backups` |

Moving the game server to the cloud: run `server` there, set `VITE_SIEGE_SERVER_URL` to its URL, rebuild the client. If the site and game server end up on different origins, the admin page's HTTP calls would also need CORS on `/api/admin` (sockets already allow any origin).

How to run it at the event, the admin page, load test, backups and the event-day checklist: see [README.md](README.md).

## Layout

```
shared/   config.ts (ALL balance numbers), world.ts (the shared map), layout.ts (one base plot), engine.ts (combat),
          pve.ts (zombie sieges), snapcodec.ts (packed snapshots), pvp.ts (raids), crates.ts (answer checks, rarity, boosts), economy.ts, types.ts
server/   index.ts (http + socket.io + game loop), game.ts (authoritative state), net.ts (protocol),
          store.ts (storage interface + SQLite), data/questions.json (crate question bank)
client/   index.html (site home), siege/index.html (game page), siege/arena/index.html (Live Arena)
          src/siege/world.ts (map renderer), stream.ts (live battle streams), main.ts (game UI), arena.ts (arena UI)
client/public/game-assets/postapocalypse/   the art pack, unmodified, with its LICENSE.txt
client/public/game-assets/graveyard/        grave_1..4.png (our own; replace freely, see shared/scripts/draw-graves.py)
```

## Decisions

- **Stack**: Node + TypeScript workspaces. Fastify + socket.io on the server, Vite + plain TypeScript (no framework) on the client. SQLite via better-sqlite3 behind a `Store` interface; every change is written immediately.
- **Authority**: the server owns coins, levels and combat. The client sends intents (`login`, `act`) and renders snapshots.
- **Combat engine** (`shared/src/engine.ts`): fixed 20 ticks/s, seeded RNG, no wall clock. Units walk straight at their target and hack through anything solid in the way; posts shoot the nearest unit in range. The same engine will run PvP in phase 2.
- **Zombie siege pacing** (`shared/src/pve.ts`, all numbers in `CONFIG.siege`): grinding bases get surges on a regular, visible countdown (banner "Surge 4 in 1:12 · from the north and east"), with nothing in between. By Main Tower level 1-8:

  | level | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
  |---|---|---|---|---|---|---|---|---|
  | gap (s) | 45 | 60 | 80 | 100 | 120 | 150 | 180 | 210 |
  | sides | 1 | 2 | 3 | 4 + graveyard | 4 + gy | 4 + gy | 4 + gy | 4 + gy |
  | base size | 10 | 16 | 20 | 26 | 32 | 38 | 44 | 50 |
  | + per firepower | 0 | 0 | 5 | 6 | 6 | 6 | 6 | 6 |
  | arrival window (s) | 32 | 33 | 35 | 37 | 40 | 43 | 45 | 47 |
  | pulses | 2 | 2 | 3 | 3 | 3 | 4 | 4 | 4 |
  | Big share | 0 | 0 | 8% | 10% | 12% | 13% | 14% | 15% |
  | Axe share | 0 | 0 | 0 | 12% | 15% | 17% | 18% | 20% |
  | boss chance | 0 | 0 | 0 | 0 | 0 | 50% | 75% | 100% |
  | hold bonus | 20 | 45 | 60 | 60 | 40 | 40 | 40 | 40 |
  | call early (coins/s skipped) | 0.4 | 0.5 | 0.6 | 0.8 | 1 | 1.3 | 1.6 | 2 |

  Surge size = (base + perFire x firepower) x pressure, max 160 (firepower = Smalls/s the posts can kill, so from level 3 surges keep up with the defence). A surge arrives in pulses (each within 4 s, from all its sides; pincers on 2-3 sides from level 5) and lasts about 30-50 s (measured 32-52). Kill coins are flat with level (Small 2, Axe 4, Big 8, boss 60); holding a surge pays the hold bonus. Zombie health and damage grow 25% per level. Afterwards everything is fully repaired.
- **Early play is guided**: a new player's first surge (director surges = 0) is a walkthrough: 8 Smalls from one side over 14 s, the Main Tower can't drop below half health, and coach prompts walk through it ("Tap the zombies to shoot them!", "Nice shooting!", then "Held! Now buy a post: tap a glowing + slot", then a note about the arrows). Below Main Tower 3: small fixed surges from 1-2 sides, tap aim assist (hit radius 2.2 tiles instead of 1.5), and the incoming sides shown as yellow edge arrows for the whole countdown (from level 3: its last 15 s). The boss is a Big drawn twice the size with its own health bar (900 hp before scaling, 60 coins).
- **Call early**: between surges, a button calls the next one now and pays coins per second skipped (into the vault, like kills). It opens once 40% of the countdown has passed (so a gap shrinks by at most 60%) and needs 3+ s left; the button shows when it opens and what it pays.
- **Difficulty**: a director nudges pressure (0.7-2.5) to keep 80% (first 5 minutes) / 85% of surges held, eases off mid-surge if the Main Tower drops below 45%, and a breach costs 5% of coins (max 60, never below 100) then the normal countdown. Measured (`shared/scripts/siege-balance.ts`): new players hold every walkthrough (16/16) and every guided surge; typical bases at every level hold their surges, and even posts two levels behind hold 95-100%, because siege posts reach 11 tiles (every post covers every side). The difficulty that shows is size, sides, types and bosses; breaches need a base that has really fallen behind.
- **What grinding pays** (typical base, tapping 2/s): coins per surge 42 / 79 / 194 / 291 / 397 / 490 / 574 / 631, per minute waiting out each countdown 34 / 54 / 105 / 132 / 156 / 160 / 160 / 154, calling every surge as early as allowed 64 / 104 / 201 / 263 / 324 / 357 / 385 / 401 (levels 1-8). A new player tapping and buying reaches Main Tower 2 in 15 minutes (3 if they call surges early).
- **Offline**: grinders nobody is looking at play one surge at a time headlessly at a coarse 10 ticks/s, then the level's countdown before the next (same rules; attack timers carry their remainder so fire rates stay exact), ~2.5 ms per chunk. The siege-balance script compares coarse and live: held share and income agree within a few percent. Coins go into a bank capped at 500, credited with a summary at the next login.
- **Upgrades** join a running siege at once (a new post starts shooting immediately); a raid keeps the base it started with. A defence boost arriving or running out is picked up within a second.
- **Open world** (`shared/src/world.ts`): one 156x156-tile city built from a fixed seed, so server and every client generate the identical map with nothing sent over the wire. 64 compounds (14x14 plots) in a 4x4 grid of city blocks of 2x2; 2-tile alleys inside a block, 4-tile streets between blocks, wrecks and barrels along the kerbs, a scenery belt around the city. New players get the free plot nearest the centre; empty plots show faded ruins. The default view centres on your block: 8 bases on a 1080p screen (4 whole, 4 mostly), 8 whole on a phone.
- **Base**: a 14x14 plot with a walled compound (36 wall pieces), Main Tower in the middle, a vault just inside the north wall (2x1, `VAULT_RECT`; health 250 + 90 per Main Tower level), 8 post slots unlocked by Main Tower level (2, 3, 4 ... 8). The ring of ground outside the walls is the raid deployment zone. The vault art is our own (`shared/scripts/draw-vault.py` writes `client/public/game-assets/vault/`; the pack has no safe), intact and cracked open; tapping it shows what's at stake. Zombies treat it like any other building in their way.
- **Graveyards**: one per block, where its alleys cross: 6-10 graves on the alley tiles (never inside a plot), mud spilling into the yards' corners. It serves the block's 4 bases with a 2-8 tile walk that never crosses another compound (checked by `shared/scripts/world-check.ts`). Zombies rise there (the death animation played backwards plus a dirt puff) and only target their own base. A pulsing marker shows over the graveyard and on the minimap during the warning and the wave.
- **Area of interest**: each screen tells the server which bases it's looking at (up to 6 nearest in view at zoom 2 or more, plus its own and any raid target). Only those get live waves and snapshot streams; every other base resolves waves headlessly every 45 s. Everyone gets a small world summary (levels, trophies, shield, raid, wave flag) on connect and changes every 0.5 s.
- **Commander (tap-to-attack)** (`CONFIG.commander`, `Siege.tap` / `Siege.airstrike` in `shared/src/pve.ts`): your survivor stands just below your Main Tower and shoots where you tap during your own base's siege, turning to face the shot (the pack's Side, Side-left, Up and Down sprites; layer offsets in `COMMANDER_LAYERS`, `client/src/siege/sprites.ts`). A tap hits the zombie closest to the tap point within 1.5 tiles (found with the engine's spatial hash, so taps stay cheap at hundreds of zombies); with none there the shot flies on toward the point and hits the first zombie within 0.45 tiles of its path. Taps count anywhere within 6 tiles of your plot, all the way round, past the walls (on a neighbour's plot the client opens their base instead, unless one of your zombies is right there). A short tap (under 450 ms, under 8 px of movement) fires; drags pan and pinches zoom without shooting. On your own base, a tap with a zombie under it fires, a tap on the Main Tower, a slot or a wall opens its card, anything else fires.
- **Server authority**: the client sends `tap {x, y}` and draws the flash, tracer and casing at once (prediction); the server checks it's your base, the siege is on and the point is in reach, enforces the fire rate (1 tick of slack for jitter), magazine and reload, resolves hits in the combat engine and broadcasts the result to everyone watching the base (spectators see the Commander turn and fire), with damage numbers, sparks and kill hit-markers. Every tap gets an answer (refusals go only to the shooter and resync the ammo bar). Damage cap: tap damage per second can't exceed half the posts' DPS (a third of the total defence), with a floor of 16 so a starter base's Commander still matters; up to 1.5 s of it can be spent at once, and shots beyond it hit softer. Crate attack boosts raise tap damage and the cap (without using up a raid charge).
- **Weapons** (bought from the Main Tower card): Pistol (free; 7 dmg, 5/s, 12 rounds, 1.1 s reload), Gun (Main Tower 2, 300 coins; 10 dmg, 5/s, 24 rounds, 1.5 s), Shotgun (Main Tower 3, 700 coins; 5 pellets x 8 over 1.4 tiles, 2.5/s, 6 rounds, 1.8 s). Combo: every 8 kills in a row without a miss adds x1 (max x3) to the coins from tap kills; a shot that hits nothing, or 5 s idle, resets it. Airstrike: every 25 s, tap the ✈ button (or Q) then the map; after a 1.2 s warning ring it deals 45 x the zombie hp scale to everything within 2.6 tiles (clears a clump of Smalls and Axes; Bigs survive). R reloads, Esc cancels aiming. Sounds: a shot per weapon, dry click, reload, combo-pitched kill tick, airstrike whistle and boom, all on the shared mute. Crosshair cursor over the map; small shake on shotgun shots and airstrikes.
- **Balance with taps** (`shared/scripts/siege-balance.ts`, simulated players tap the zombie nearest the Main Tower): first 5 minutes, a casual tapper (2/s, sloppy aim) holds 84% of surges, a keen one (3.5/s) 88%, an autoclicker at 5/s with perfect aim 94%, a player who never taps 74%. Taps make 18-30% of kills (never the majority). To get there the director's ceiling went from 1.6 to 2.6, and in a player's first 5 minutes a surge held without the Main Tower dropping below 90% raises pressure 2.5x faster, so tappers reach the target quickly. Settled non-tapping bases still hold 76-83%. Offline sieges use at most pressure 1 (`offline.pressureCap`), since nobody taps while you're away.
- **Load test with taps**: every bot taps its own zombies at the full 5/s and calls airstrikes. 50 bots, 90 s: 16,417 taps (183/s), all but 3 answered, zero "too fast" refusals, airstrike p95 5 ms, tick avg 2.4 ms (max 15 ms), 118 MB.
- **Snapshots** travel packed (`shared/src/snapcodec.ts`, 9 bytes per unit) 6.7 times a second (`CONFIG.snapshotEvery` 3); clients interpolate. Load test, 50 bots + 3 spectators for 90 s: 1.6 KB/s of snapshots per screen, tick avg 2.9 ms (max 17 ms of the 50 ms budget), 120 MB.
- **Siege feel (client)**: a red arrow pulses at the screen edge toward the side of your base under the heaviest pressure (the server sends per-side pressure twice a second, so it works off screen too); a red vignette pulses when your Main Tower is hit; growls (filtered noise + wobbling saw, panned toward the busy side) come more often as the pressure rises; a siren for the first surge and pincers, a boom on a breach, a chime when a surge is held. The sound button in the top bar shares its mute switch with the title screen (`siege.muted`). The banner shows the surge, zombie count and breather countdown on one line.
- **Siege rendering**: unit views are pooled, depth sorting reuses one list, left-facing zombies use the pack's Side-left sheets (no canvas transforms), zoomed out (below 1.75 device px per art px) units drop to a still frame without shadow or health bar, and the compound yard is one cached image. Measured in the browser at 1920x1080 (devicePixelRatio 1.25, canvas 2400x1196) with 300 zombies through the real snapshot path: default zoom, 7 live bases: draw 1.5 ms median / 2.4 ms p95; 15 live bases: 1.7 / 2.6 ms; whole city at zoom 1 with all 40 bases live: 2.9 / 4.4 ms; 500 zombies: 2.6 / 4.0 ms. The pane ran at 100-140 frames/s throughout; its occasional 20 ms gaps also happen with no zombies at all.
- **Rendering**: integer zoom only (crisp pixels). Ground, graves and scenery are baked into 512px chunks once; quiet bases are cached as one image; only watched bases animate. Name tags are drawn in screen pixels.
- **Raids (PvP)** run on the map where the base is: the attacker taps the red zone around the target to send raiders (coins charged by the server, up to 40). **No countdown.** A raid ends when everything that counts is destroyed (Main Tower, posts and vault; walls don't), when every raider is dead and the attacker can't send another (troop limit, or not enough coins for the cheapest one unlocked), or when they tap End attack. Anti-stall (`CONFIG.pvp.stall`): 15 s with no damage dealt by either side after the first deploy ends it; nothing deployed within 30 s cancels it at no cost to anyone (the attacker gets back the immunity and boost charges the attack used, no trophies move, no shield); a hidden failsafe ends any raid at 6 minutes (never shown). Raiders always act: melee walks to the nearest building, ranged walks until it's in range, walls in the way get hacked (tested: no raider is ever idle). Rewards come from what was destroyed when it ended, however it ended: stars (1 for 50% of what counts, 1 for the Main Tower, 1 for everything; a win is 1+ star), loot = the stake (20% of the defender's coins, capped at 300 + 150 per Main Tower level, never below 100, reduced against much weaker players) x (50% if the vault was cracked + 50% x destruction), paid even without a star; trophies: a win pays stars/3 of the stake (30 +/- 5% of the gap, 5-50), a 0-star raid costs half of it. The defender gets a 2-minute shield. The attack bar, Live list, arena scoreboard and result cards show stars, destruction, vault and raiders left instead of a clock. Anyone can spectate from the Live list or a base's card.
- **Modes** (`CONFIG.modes`, toggle next to the banner): **Grind** (PvE): your base gets the zombie siege, kill coins fill your vault, you can't launch raids. **Raid** (PvP): the swarms hold off your base and you can raid. New players start grinding; the mode is saved and kept across disconnects. Switching has a 60 s cooldown (reset the moment a raid you launched ends, so you can go straight back to grinding) and is locked during a surge (switch in the breather) and while you're attacking or being attacked. Any base can be raided whatever its mode, unless immune or shielded; a raided base's swarms pause until the raid ends, in either mode. Offline, only grinders' sieges keep resolving headlessly (bank cap 500, and the vault cap). The feed announces switches. Each base's map tag shows a GRINDING / RAIDING chip, plus VAULT FULL for a grinder at 90%+ of capacity (the best loot). Both leaderboards (Ranks panel, Live Arena) show each player's mode; trophies come only from raids.
- **Vault capacity** (`CONFIG.vault.capacity`, by Main Tower level): 500, 1000, 1800, 3200, 5200, 8000, 12000, 16000 (always room for the next Main Tower upgrade). Zombie kill coins (posts and taps) stop once it's full; raid loot and crate coins can go over.
- **Raid rewards with modes**: stolen loot = 30% of the defender's coins (capped at 300 + 150 per Main Tower level, never below 100) x (50% for the vault + 50% x destruction), plus a **star bonus** in new coins (per star, by the defender's Main Tower level: 38, 45, 65, 100, 170, 225, 290, 370). Both scale by the **match factor** (`CONFIG.pvp.match`): trophy gap (down to x0.25 against a base 400+ trophies weaker, up to x1.5 against one 400+ stronger) times Main Tower gap (x0.2 per level, 0.3-1.6); stolen loot never goes above x1, the star bonus does. Trophies: 30 x the match factor (5-50), stars/3 of it for a win, half of it lost for 0 stars. Raiders are cheaper: Bat 12, Pistol 15, Brute 30, Shotgun 27.
- **Grind vs raid** (`shared/scripts/economy-balance.ts`; the cheapest army that wins 70%+ against a same-level base, dropped at 2-3 points; defender vault 60% full; 25 s overhead per raid; grinding waits out each countdown): HQ1 grind 36/min, army 96 = 2.3 surges, raid nets 55/min (x1.5 grind); HQ2 51/min, 210 = 2.5 surges, 110/min (x2.2); HQ3 96/min, 369 = 2.1 surges, 188/min (x2.0); HQ5 127/min, 600 = 1.9 surges, 456/min (x3.6: rich defenders). Star bonus per star by defender level: 38, 45, 65, 100, 170, 225, 290, 370. The risk: a lost raid costs the whole army, and the target can be stronger than it looks.
- **Raid balance with the vault and no timer** (`shared/scripts/pvp-balance.ts`, raiders dropped at one corner): 5 Bats now 3-star a starter base (4 fall short: one of them goes for the vault); HQ2 base: 6 Bats + 4 Pistols fail, 8 + 5 win 2 stars, 10 + 6 win 3 stars; HQ3: 2 Brutes + 6 Bats + 4 Pistols win (was 1). The HQ5 sample army (4 Brutes, 6 Shotguns, 6 Bats from one corner) used to win by sniping the Main Tower and now runs out at 25%: raids reward hitting what counts, the vault included, so spreading raiders around matters more.
- **Immunity**: buy 5 min (150 coins) or 10 min (250) of protection from raids; buying again extends it, up to 15 min left. It doesn't stop zombies. Attacking anyone ends it. Immune bases show the shield icon and can't be targeted (the card says why).
- **Crates**: one global crate every 10 minutes (first one 1 minute after the server starts), landing at the crossroads in the middle of the map with a question from the bank. No question repeats until the bank is used up; an unclaimed crate expires when the next one drops. The schedule, the used-question list and the current crate are saved in the database (`meta` table), so a restart doesn't reset them. Answers are checked only on the server and never sent to clients until the crate is claimed. Checking ignores case, outer quotes, a trailing `;`, commas and extra spaces (and for fill-in-the-blank, all spacing). Wrong answers: 3 s wait, and every 5th wrong answer locks you out for 30 s. **Exactly one winner**: the check and the claim run in one synchronous step on the single game thread, so two answers arriving together are handled one after the other and the second is told who won.
- **Crate rewards**: rarity green 60% / blue 30% / red 10% (`CONFIG.crates.weights`), and the rarity sets the strength. A random boost the player doesn't already have at a stronger level: attack (+25/40/60% raider damage, next 3 raids), defence (+25/40/60% post damage and health for 30 min, in waves and raids), loot (+50/75/100% on the next raid, still never taking a defender below 100 coins). One boost of each type; an equal or stronger one replaces it. If every type is already stronger, the winner gets coins instead.
- **Spectating**: the Live Arena connects as a spectator (socket auth `{spectator: true}`, no login, no token). It gets the world summary, feed and crate, can watch at most 2 bases, and every other request is refused. It joins the same per-base battle stream (`base:<plot>` room) the attacker and defender use, so it sees exactly what they see. It auto-picks a live battle and moves to the next one when it ends (after a 6 s result card). Projector mode also rotates between live battles every 20 s, uses big type, and shows a large leaderboard over a slowly drifting map when nothing is happening. Players can also spectate inside the game (a base's card or the Live list).
- **Feed** also announces rank changes: climbing into the top 3, or to #1, after a raid.
- **Admin** (`/siege/admin/`): a plain HTTP API (`/api/admin/*`) checked against `SIEGE_ADMIN_PASS` in an `x-admin-pass` header (constant-time compare, 5 wrong tries per minute per address, then a 1-minute lockout); the page keeps the passphrase in sessionStorage only. Pause stops the simulation but not summaries, and on resume shifts every wall-clock timer by the pause. Freeze is display-only (summaries show a trophy snapshot). Pause/freeze survive a restart (store meta `admin`). Deleting a player first logs out their open screens, since SQLite can hand a deleted id to the next newcomer.
- **Robustness**: the game loop catches and counts errors per tick instead of crashing the process; health numbers (tick time, loop lag, memory, errors) are on `/api/health` and the admin page. Server settings can live in `server/.env` (gitignored).
- **Load test** (`npm run loadtest`): starts a throwaway server + database, then 50 bots and 3 spectators behave like players (upgrades, raids, crate races, reconnects). On the dev laptop: p95 5 ms, ticks ≤ 4 ms, 112 MB, exactly one winner per crate.
- **Known limit**: raids in progress when the server restarts are dropped (coins already spent on raiders are not refunded). Everything else survives.
- **Dev server gotcha**: `tsx watch` can miss edits to `shared/`; if the server behaves like old code, restart `npm run dev`.
- **Theme**: `client/src/theme.css` is the one place for every colour, font and size: the page UI (top bar, banner, buttons, panel, minimap, arena, admin) uses only its CSS variables, and the map canvas reads its `--map-*` values at start-up (`client/src/siege/theme.ts` holds no values, only the reader and the remap/colour helpers). Fonts are bundled from `client/public/fonts/` (no internet); until those files are added, system fonts are used. Touch targets are at least 48 px.
- **Fonts**: three bundled OFL pixel fonts in `client/public/fonts/` (46 KB): Press Start 2P for the logo, menus, headings and buttons (`--font-display`; plus an unscaled `Siege Pixel` face for pixel-exact canvas text), Pixelify Sans for body text and map tags (`--font`), VT323 for numbers and code (`--font-mono`).
- **Title screen** (`client/src/siege/title.ts`, `titleScene.ts`, `retro.ts`): what anyone not logged in sees. One canvas at 320x180 (180x320 on portrait phones) scaled by whole numbers and letterboxed. Attract mode: four survivors (gun, pistol, shotgun, bat) hold a ruined street built from the pack's facade tiles, doors, awnings and wrecks while Small/Axe/Big zombies walk in (left-facing walk/attack/death sheets), with muzzle flashes, bullets, white hit flashes, blood, shotgun shake and a 2x boss every 20-40 s; spawn timing is randomised. Fire-gradient logo with outline, shadow, rare flicker and glitch; live top 3 + players online from `GET /api/summary` (falls back to "SERVER OFFLINE"). Menu: START GAME (retro login: real invisible inputs sit over the drawn fields, so phone keyboards, paste and screen readers work; same one-account-per-roll rules), HOW TO PLAY, LEADERBOARD (`/siege/arena/?board=1`, the arena's big leaderboard), LIVE ARENA. Keyboard (arrows/WS, Enter, Esc, M sound, C CRT), mouse hover/click, touch tap; hidden real buttons + a live region for screen readers. WebAudio blips start after the first interaction; mute and CRT scanlines are toggles remembered per device. The loop stops while the tab is hidden; nothing loads from the internet.
- **Look** (canvas colours come from `theme.css`): the pack's Green ground tileset, recoloured at load time by per-tile-type palette rules (vivid grass, warm earth; the files are untouched); streets are a generated deep-blue asphalt texture with kerbs and dashed yellow centre lines. Soft shadows under scenery, graves and bases are baked into the chunks. Live on screen only: swaying grass (the pack's 2-frame grass sheets), each base's waving banner in its own colour (golden-angle hue from the player id; name tags and minimap use the same colour), drifting fog and rising embers at graveyards (stronger during a wave), and a light rain shower for 75 s every 6 min by the wall clock (same on every screen) with streaks, drop splashes and puddles using the pack's splash animations. A CSS vignette layer darkens the edges at no canvas cost.
- **Survivor posts** are layered sprites (body without hands + weapon-with-hands + helmet from Lv 4). Layer offsets live in `client/src/siege/sprites.ts` if anything looks misaligned.
- **Main Tower** has no sprite in the pack: it's a shipping container that changes colour and gains antennas/AC/barrels with level.
- **Login**: display name + roll number; one account per roll number and the name must match on return. The session token lives in localStorage.
- **Questions**: 30 short-answer questions (fill-in-the-blank, predict-the-output) in C, C++ and Python: 13 from v1 plus 17 new ones, each checked by actually running the code. v1's write-a-function questions were dropped (they needed a code sandbox). Add more by editing `server/data/questions.json` (id, prompt, code, lang, kind, answers, difficulty) and restarting the server; a test checks every question accepts its own answers.
- **Combat pace** (`CONFIG.pace`): raiders walk 1.6x and they and the posts attack 30% more often. Zombies keep their speed: the denser city already cut their walk to ~5 tiles, which speeds waves up by itself. To keep it fair, posts got -5% damage / +10% health and kill coins -15%. Checked with `shared/scripts/pve-balance.ts` and `pvp-balance.ts`: income within ~10% of before, a neglected base is breached 13% of waves (was 10%), and every raid tipping point is unchanged (e.g. 3 bats lose / 4 win vs a starter base); raids are ~30% shorter.
- **Pacing** (from `shared/scripts/pve-balance.ts`): about 22 coins/min at the start, 39/min with two pistols, around 93/min at Main Tower Lv 2; new players start with 120 coins, enough for a second post straight away.
